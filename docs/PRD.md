## 2. 产品定义

TK-OPS 面向需要同时运营多个 TikTok 账号的内容创作者。每个账号拥有独立定位、知识库、内容计划、生产批次、内容资产、发布配置与复盘数据。用户通过左下角账号切换器切换整个工作区，而不是对同一数据表做筛选。

产品的核心价值是：

1. 让不同账号按各自定位和知识上下文稳定生产内容。
2. 把选题、脚本、分镜、视频拆解、视频镜头、配音、字幕、自动合成、发布和复盘组织成可追踪的创作链路与批次。
3. 默认只让用户关注当前批次、异常项和下一步动作，减少逐条重复操作。
4. 让所有长任务可见、可取消、可重试、可恢复，并能追溯到账号、知识快照、Provider 和版本。

TK-OPS 不是经营后台、团队协作平台、重 CRM 或专业非线性剪辑器。

## 3. 用户与核心场景

### 3.1 目标用户

- 同时运营多个 TikTok 账号的个人创作者。
- 需要按账号定位批量生成内容的运营者。
- 需要本地优先、可审计任务与发布环境的自动化操作者。

### 3.2 核心场景

#### 场景 A：按账号建立定位和知识

用户选择账号，维护受众、内容支柱、表达风格、品牌事实、禁用规则、参考内容和发布约束。AI 只能读取当前账号已启用的知识来源和定位版本。

#### 场景 B：创建批次并批量生产

用户从内容计划创建生产批次，确认目标、数量、模板、素材来源和发布节奏。系统批量生成内容变体，并按阶段推进脚本、分镜、镜头、配音、字幕与自动合成。

#### 场景 C：先完成脚本与分镜

用户从当前账号选题池建立单条或多条内容，使用账号定位和知识快照生成、编辑并采用脚本版本，再基于已采用脚本生成和校对分镜。确认分镜后，内容进入统一批量生产与自动合成链路。

#### 场景 D：拆解参考视频并回流

用户导入本地视频或当前账号内容库中的已授权素材，查看带时间证据的脚本文案、关键词、关键帧和内容结构，选择性创建选题，或写入脚本、分镜、知识库与资产。写回已有版本前必须确认影响范围。

#### 场景 E：使用轻量媒体工具

用户对自有或获授权素材执行链接下载、去水印、转码压缩、音频提取、关键帧提取或比例裁切。所有任务、日志和输出绑定当前账号，完成后写入当前账号内容库。

#### 场景 F：只处理异常

正常结果默认折叠。用户优先处理缺素材、生成失败、低置信内容、字幕溢出或发布预检失败，并可在最小失败范围内重试。

#### 场景 G：发布与复盘回流

成片通过真实账号、工作区和执行绑定完成预检与发布。真实回执和表现快照形成可执行建议，并由用户确认回流定位、知识库或下一轮内容计划。

## 4. 产品边界

### 4.1 V1 必须覆盖

- 首启、许可证、一机一码、目录初始化和 Runtime 健康检查。
- 多 TikTok 账号工作区及真实账号绑定。
- 每账号独立定位、知识库、品牌资产与生成规则。
- 选题矩阵、策划简报、脚本生成 / 编辑 / 版本和批次创建。
- 脚本结构对照、分镜生成、镜头级校对、版本确认和进入批量生产。
- 视频导入、解析 / 转录、关键词、分段、结构提取，以及结果创建选题或回流脚本、分镜、知识库与资产。
- 批量脚本、分镜、视频镜头、配音、字幕和自动合成。
- 成片预览、镜头级重生成、版本选择、异常重试和整批取消。
- 账号级媒体工具箱：视频链接下载、去水印、转码压缩、音频提取、封面 / 关键帧提取和比例裁切。
- 内容库、发布预检、发布任务、真实回执和复盘回流。
- 真实 PC 工作区、浏览器实例、执行环境和 Provider 配置。
- Provider、真实模型、能力契约、Prompt、视觉风格、合成模板和账号 AI 配方的完整配置链。
- 统一任务总线、日志、异常处理和配置总线。

### 4.2 明确不做

- AI 剪辑工作台、手动多轨时间线、拖拽编排、逐帧裁切、吸附、轨道锁定和专业特效。媒体工具箱允许一次性比例裁切和受控转码，但不形成剪辑器。
- 订单、退款、商品、库存、客服、团队审批、成员权限和经营报表。
- 伪造账号、设备、工作区、浏览器实例、发布回执或业务指标。
- 高风险设备伪装、平台风控规避或不受控自动化。
- 绕过登录、DRM、付费墙、访问控制或平台安全机制的下载与抓取。
- 未经权利确认的去水印、批量搬运、隐藏来源或版权规避。
- 手机、平板、移动端导航或触屏手势适配。
- V1 默认不提供动作迁移、参考视频生成、数字人或声音克隆；相关能力只能在后续完成安全、授权和数据边界评估后单独立项。

自动合成由 Runtime 内部的 `CompositionSpec` 表达。用户可以预览、切换版本、重生成镜头和重新合成，但不直接编辑多轨时间线。

## 5. 账号是租户与工作区边界

### 5.1 账号切换规则

左下角账号切换器是全局工作区入口。切换后必须同时更新：

- 页面导航状态与目标账号最近页面。
- 定位、知识来源、品牌资产和生成上下文。
- 内容计划、生产批次、内容库、任务、发布配置和复盘。
- HTTP 缓存键、WebSocket 主题、Detail Panel 上下文和 AI 会话上下文。

切换前若存在未保存内容，必须先保存、放弃或取消切换。切换中显示轻量加载状态。上一账号的后台任务可以继续运行，但不得出现在当前账号工作区；切回后才可查看。

### 5.2 数据隔离规则

- 所有账号级实体必须显式包含 `account_id`。
- Runtime 服务层和仓储层必须强制账号范围，不能依赖 UI 过滤。
- 缓存键、文件目录、任务、日志关联和 WebSocket 频道必须包含账号范围。
- 跨账号复用只能通过显式复制产生新对象和来源记录。
- 许可证、Runtime、Provider、日志框架和全局配置总线属于系统级能力。

### 5.3 每账号知识库

`AccountKnowledgeBase` 至少管理：

- 定位、受众、内容支柱和表达风格。
- 品牌事实、产品资料、视觉资产和发布约束。
- 禁用词、风险边界、常用钩子、CTA 和脚本模板。
- 历史内容、表现反馈、参考视频和对标样本。
- 来源、索引状态、版本、快照和引用记录。

生成任务必须记录使用的定位版本与知识快照。来源缺失、过期、索引失败或规则冲突时，UI 必须展示影响和恢复路径。

### 5.4 账号生命周期

账号管理从左下角账号切换器进入，属于系统级管理面，不占用账号工作区主导航。账号状态固定为：

- `draft`：已保存草稿，尚未完成创建向导。
- `unbound`：账号对象已创建，但真实工作区、浏览器实例或执行环境尚未完成绑定。
- `ready`：授权、工作区、知识库和必要 AI 能力检查通过。
- `attention`：至少一个关键依赖失效，需要用户处理。
- `archived`：停止进入生产与发布主链，但数据仍可恢复和审计。

添加账号必须依次覆盖基础身份、真实连接、定位、独立知识库、账号 AI 创作档案和健康检查。账号允许复制配置，但只复制定位模板、知识规则结构、AI 配方和发布默认值；不得复制平台授权、Provider 密钥、浏览器绑定、内容资产、知识索引、任务或发布历史。

1. 工作台。
2. 定位与知识。

Sidebar 底部依次为系统设置和当前账号切换器。账号管理通过切换器弹层进入，不占用高频主导航。

### 7.1 关键记录要求

每个 `ProductionBatch` 必须记录：

- `account_id`。
- 定位版本和知识库快照。
- 生成策略、模板和 Provider 版本。
- 输入模式、账号 AI 配方版本、批次覆盖项和模型能力快照。
- 创建人机动作、任务链、阶段耗时和日志关联。
- 取消、失败、重试、完成和确认记录。

`ContentItem` 是单条内容的创作前对象，承载选题简报、脚本版本、分镜版本、来源引用和生产引用。脚本与选题、分镜规划和批量生产必须切换同一个 `ContentItem`，禁止仅靠相同标题拼接页面数据。

`BatchEntry` 是 `ProductionBatch` 内的一条执行队列项，通过 `ContentItemReference` 不可变记录采用的 `ContentItem`、脚本版本、分镜版本和知识快照；`ContentVariant` 是该队列项生成的单条可发布聚合根。配音、字幕和合成方案从属于 `ContentVariant`，不允许形成彼此割裂的项目链。

每个 `MediaToolTask` 必须记录 `account_id`、工具定义、输入来源、权利确认、配置快照、状态、进度、超时、输出资产、错误码、日志和重试关系。工具输出只能生成当前账号的新 `Asset` 或新版本，不得覆盖原文件。

系统级 AI 配置由 `ProviderProfile`、`ModelProfile`、`ModelCapability`、`PromptProfile`、`CapabilityRoute` 和 `CompositionTemplateProfile` 组成。`AccountAIRecipe` 只能引用这些系统对象并保存账号覆盖；不得复制密钥、工作流原文或形成页面私有模型配置。

## 8. 批量生产主链

```text
选择账号
→ 读取定位与知识快照
→ 选择内容目标
→ 生成或导入选题矩阵
→ 人工确认
→ 生成、编辑并采用脚本
→ 生成、校对并采用分镜
→ 批量生成镜头、配音和字幕
→ 自动合成
→ 只处理异常与低置信结果
→ 确认成片
→ 发布预检与发布
→ 真实表现回流
```

### 8.1 批次创建

批次输入模式至少覆盖：

- 已确认内容：选择一个或多个已完成脚本采用与分镜确认的 `ContentItem`。
- AI 主题：输入主题与目标，由脚本节点生成内容。
- 固定脚本：导入或粘贴脚本，跳过脚本生成节点。
- 已有素材：选择当前账号内容库资产，由流水线补齐缺失镜头；选中图片时可进入图生视频子模式。

建批采用“输入来源 -> 内容计划与知识快照 -> AI 配方 -> 执行确认”四步流程。默认只显示目标、数量、语言、账号知识快照、账号默认配方和必要约束；模型参数、成本限制和批次覆盖项渐进披露，并通过配置总线校验。

固定脚本支持按段落、按行或按句子拆分为镜头草稿。拆分结果必须先形成可检查的脚本 / 分镜版本，再进入生产；拆分方式、原始文本引用和人工调整记录进入执行快照。

“生成单条视频”和“批量生产”必须共用同一执行模型。单条生产由系统创建只含一个 `BatchEntry` 的批次，不允许维护第二套任务、状态或资产链路。

### 8.2 生成与合成

- 阶段固定为选题、脚本、分镜、生成、合成、待发布。
- 阶段内部按脚本版本引用、视觉规划、分镜版本引用、图片 / 视频、TTS、字幕、合成 / BGM 和预览节点记录。脚本与分镜页面负责创作前确认，批次节点负责执行与追溯，两者不重复维护正文。
- 长任务状态固定为排队中、运行中、正在取消、失败、完成。
- 允许取消整批、重试失败阶段、镜头级重生成和版本切换。
- 自动合成失败不影响已成功的上游产物；重试默认从最小失败范围继续。
- 节点详情必须记录 Provider、模型、版本、能力模式、输入输出、耗时、成本、重试次数和回退路径。
- 进度必须同时支持任务级和镜头级事件，至少包含阶段、总体进度、当前镜头 / 总镜头、当前动作和附加状态。并发执行不得破坏镜头顺序或把单镜头失败误报为整批完成。
- 已有素材模式先分析真实图片 / 视频，再把素材候选绑定到分镜镜头；低置信匹配、缺失素材和替代素材必须显式确认，不允许静默回退到无关资产。

### 8.3 结果审核

- 默认用紧凑列表展示内容变体。
- 正常项提供成片预览和确认动作，不要求逐条打开。
- 异常项置顶并显示原因、影响、推荐修复、日志和重试。
- 发布成功只能来自真实平台回执；不确定结果标记为“待确认”。

### 8.4 脚本与分镜工作面

- 脚本与选题页支持选题池、策划简报、结构化预览、原文编辑、AI 生成 / 改写、版本采用与恢复。
- 分镜规划页只读取已采用脚本版本，支持脚本段落对照、镜头级生成 / 重生成、顺序调整、版本保存和确认进入生产。
- 脚本、分镜和生产详情使用同一低高度创作链状态：选题、脚本、分镜、生产、成片；只突出当前阶段和一个主动作。
- 新建选题至少支持手动创建、按账号定位 AI 推荐和从视频拆解结果创建；创建后立即形成当前账号的 `ContentItem`。
- 分镜确认后必须提供“生成单条视频”“加入现有批次”“创建新批次”三种交接方式，并明确展示采用版本和目标批次。
- 检测到脚本更新时，旧分镜必须标记基于的脚本修订，并要求用户同步或继续使用旧版本。
- 两页都记录定位版本、知识快照、Provider、模型、AI 作业和采用记录。

### 8.5 视频拆解

- 输入只允许本地视频、当前账号内容库资产或当前账号媒体工具输出。
- 阶段至少覆盖导入 / 元数据、视频解析或转录、分段、结构提取和结果确认。
- 标准结果包含脚本文案、关键词、关键帧和内容结构，并分别使用与数据语义匹配的表格展示。脚本段必须带时间码、段落作用和置信度；关键词必须带分类、权重、命中次数和证据时间点；关键帧必须带真实缩略图、镜头作用、画面摘要和可复用方向；结构段必须带起止时间、时长占比、作用、对应文案和证据关键词。
- 内容结构上方必须提供整条视频的一至两句特点总结、主要叙事类型和可复用 `featureTags`。无真实结果时显示中性空态，不生成假转录、假标签或假关键帧。
- 用户可以选择创建选题、写入脚本、分镜、知识库或图片资产。应用前必须预览将创建或修改的对象；覆盖已有版本前显示影响并确认，写回默认生成新版本和来源记录。
- Provider、FFprobe 或源文件不可用时，保留已成功阶段并提供诊断、重试和重新导入路径。

### 8.6 媒体工具箱

- V1 工具固定为视频链接下载、去水印、转码压缩、音频提取、封面 / 关键帧提取和比例裁切。
- 页面只显示工具目录和最近任务；点击工具后通过统一向导完成输入、配置、权利确认和执行确认。
- 任务状态固定为排队中、运行中、正在取消、失败和完成，并提供取消、重试、打开输出和导入内容库。
- 下载不绕过登录、DRM、付费墙或访问控制；去水印只处理用户确认自有、公共领域或已获授权内容。
- 输出保留原输入、工具版本和配置快照，生成当前账号内容库的新资产或新版本。

### 8.7 内容库分类与溯源

- 主类型固定为全部、视频、图片、音频和文档，与真实资产 `type` 一致。
- 次级筛选使用用途、来源和状态；模板使用 `purpose=template`，媒体工具输出使用 `source=media-tool`，不得与媒体类型混为同一维度。
- 内容库至少支持成片、创作素材、脚本 / 字幕文档、模板、拆解输出、媒体工具输出和本地导入的筛选与溯源。
- 视频、图片、音频和文档分别展示与类型匹配的元数据；详情必须能回溯 `ContentItem`、批次、拆解任务、媒体工具任务或本地导入记录。
- 脚本与分镜继续以版本化业务对象为真源；进入内容库的文档资产是归档或导出引用，不得反向形成第二份可编辑正文。

## 9. 状态、异常与反馈

每个关键页面必须覆盖加载中、空状态、正常状态、错误状态和受限状态。业务空态统一区分 `first_use`、`no_data`、`filtered_empty`、`dependency_blocked`、`waiting_external` 和 `restricted`；空态由当前账号真实数据和依赖推导，不能由全局演示开关替代页面判断。

空态只提供一个与当前前置条件一致的主动作。例如脚本与选题为空时“新建选题”，分镜缺少采用脚本时“返回脚本并采用”，批量生产缺少已确认内容时“继续创作”，筛选为空时“清除筛选”。

统一错误恢复链：

`中文摘要 -> 受影响账号/批次/内容 -> 技术详情折叠 -> 推荐修复 -> 重试 -> 刷新状态`

所有自动化、发布、渲染和 AI 长任务必须具备：

- 超时与取消。
- 失败原因和关联日志。
- 最小范围重试。
- WebSocket 断线重连与最终状态补拉。
- 缓存失效、任务刷新和全局状态广播。

Runtime 统一信封：

- 成功：`{ "ok": true, "data": ..., "meta": { ... }? }`
- 失败：`{ "ok": false, "error": "...", "error_code": "STABLE_CODE", "log_id": "log_xxx"?, "fieldErrors": []?, "meta": { ... }? }`

请求关联由 `X-Request-ID` Header 返回。`log_id` 只在用户可见错误或诊断记录实际生成时返回；错误信息必须可安全转换为中文 UI 提示，不得直接暴露 traceback、密钥、完整 Prompt 或完整账号凭据。

## 10. 数据真实性与授权

- 生产页面必须由真实 Runtime 数据驱动。
- 无真实数据时使用中性空态或引导态，不填充看似真实的业务数字。
- 交互原型可使用明确标注的演示账号和演示内容，只用于验证账号隔离和流程，不代表后端结果。
- 授权、一机一码、目录初始化和 Runtime 健康检查必须走真实链路。
- 账号、设备、工作区、浏览器实例与执行绑定必须是真实对象。
- 视频下载和去水印在执行前必须记录内容权利确认；生产实现需要明确支持来源、平台条款、依赖许可证和地区版权边界。
- 媒体工具不得静默覆盖源文件；失败、取消或超时必须保留输入和可恢复状态。

## 11. AI 能力边界

统一 Provider 接口：

- `ScriptProvider`
- `ImageGenerationProvider`
- `VideoGenerationProvider`
- `TTSProvider`
- `SubtitleAlignmentProvider`
- `AssetAnalysisProvider`
- `VideoAnalysisProvider`
- `SpeechToTextProvider`
- `EmbeddingProvider`

系统通过 `ModelCapabilityRegistry` 声明模型真实支持的文生图、文生视频、图生视频、参考图、原生音频、时长、比例、分辨率与并发限制。能力记录必须区分供应商声明、当前适配器已接入和已完成契约验证三种事实，并保留来源、已知限制和验证时间。页面不得硬编码供应商、展示未接入参数或假设所有模型能力相同。

AI 配置对象固定为：

`ProviderProfile -> ModelProfile -> ModelCapability -> CapabilityRoute -> PromptProfile`

系统、账号与任务的继承固定为：

`系统 CapabilityRoute -> 账号 AI 创作档案 -> 单次批次覆盖`

- Provider 凭据、Base URL、代理和区域只属于系统配置与安全存储。
- Provider 支持直接 API、OpenAI-compatible、ComfyUI 和 RunningHub 适配方式；适配来源不得改变产品能力语义。
- `ModelProfile` 保存真实模型 ID、启用状态和基础限制；`CapabilityRoute` 为选题、脚本、分镜、拆解、转写、图像、视频、TTS、字幕和 Embedding 指定主模型、回退模型与 Prompt。
- `PromptProfile` 版本化保存系统提示、任务模板、变量、输出 Schema、视觉风格前缀和安全约束。合成模板使用独立 `CompositionTemplateProfile` 保存类型、画幅、参数 Schema、预览和兼容能力。
- 账号只保存 Provider Profile 引用、模型配方、视觉风格、音色、模板、成本上限和回退策略。
- 批次覆盖只对当前批次生效，不反向修改账号或系统默认值。
- 每次调用记录账号、能力、模型、Provider、版本、耗时、成本、结果状态、知识快照、配方版本和失败原因。
- 模型专属的时长、比例、分辨率、负向提示、原生音频和水印参数只在“适配器已接入且契约已验证”时出现，并进入不可变执行快照。
- 内容审核或 Provider 拒绝时可以提供安全改写建议，但不得静默修改原 Prompt 或创作意图；用户确认后生成新版本并保留原因。

V1 默认支持主题转视频、固定脚本转视频、已有素材辅助和图生视频。参考音色、数字人、动作迁移和参考视频生成不进入 V1 默认路径。

上述流水线与能力契约参考 [`ATH-MaaS/Pixelle-Video`](https://github.com/ATH-MaaS/Pixelle-Video) 的公开实现，但 TK-OPS 必须重新落入账号隔离、配置总线、版本确认、安全凭据和可审计任务边界，不能直接复制其单工作区 WebUI。

## 12. 非功能要求

- 本地优先，网络或 Provider 暂时不可用时保留可浏览数据和恢复入口。
- Light / Dark 双主题结构一致。
- 覆盖 `1440×900` 宽屏与约 `1180×760` 紧凑 PC 窗口，不设计移动端。
- 页面主体禁止整体横向滚动；表格、日志和批次列表可局部滚动。
- UI 代码按页面、composable、helpers、types 和 styles 分层。
- 所有配置通过统一配置总线，所有请求通过 Runtime 适配层。
- 所有异常必须捕获并记录，UI 必须有可见反馈。
- 数据库启动必须先完成结构识别、迁移和目标契约校验；未知结构只读失败，禁止猜测修补。迁移失败不得继续开放 Runtime 业务写入，并必须提供中文诊断与安全恢复路径。

## 13. 优先级与里程碑

### P0：账号基础与隔离

- 许可证、Runtime 和工作目录真实链路。
- 账号工作区上下文、左下角切换器和隔离契约。
- 账号创建、真实连接、健康检查、配置复制、归档与恢复。
- 定位与知识库基础对象、来源、索引和快照。
- 系统 Provider Profile、模型能力注册和账号 AI 创作档案。

### P1：计划与批量生产

- 选题矩阵、脚本策划、脚本版本、分镜规划和创作前确认。
- 视频拆解、脚本 / 关键词 / 关键帧 / 结构结果，以及选题 / 脚本 / 分镜 / 知识 / 资产选择性回流。
- 媒体工具能力注册、六个 P0 工具、统一任务状态和输出入库。
- 建批和批次阶段状态。
- 主题、固定脚本、已有素材和图生视频输入模式。
- AI 节点生成、自动合成、异常优先审核、预览和最小范围重试。
- 内容库与版本归档。

### P2：发布与复盘

- 真实工作区、执行绑定和发布预检。
- 发布任务、真实回执、失败恢复和复盘回流。

## 14. 验收标准

1. 切换账号后，页面、数据、缓存、任务视图和 AI 上下文不残留上一账号内容。
2. 每个账号拥有独立定位与知识库，生成结果能追溯到版本和快照。
3. 正常工作区有十个账号级主入口，脚本与选题、分镜规划、视频拆解和媒体工具箱可直接发现，账号切换器固定在左下角。
4. 产品中不存在 AI 剪辑工作台、手动多轨时间线或专业剪辑承诺。
5. 批次可完成创建、生成、异常处理、预览、确认、发布与复盘回流。
6. 加载、空、正常、错误、取消、重试和完成状态可见且可恢复。
7. 不展示无来源的真实感业务数字，不伪造账号、设备、绑定或回执。
8. PC 宽屏和紧凑窗口均可完成主链，Light / Dark 语义一致。
9. 账号管理可以完成创建、真实连接诊断、配置复制、归档与恢复，所有动作有可见反馈。
10. 系统 Provider、账号 AI 配方和批次覆盖的继承来源明确，生成任务可追溯到节点、模型与成本。
11. 脚本采用后可进入分镜，分镜确认后可进入批量生产；脚本更新不会静默覆盖旧分镜。
12. 新建选题能形成独立 `ContentItem`；分镜确认后可生成单条视频、加入现有批次或创建新批次，且三者共用批次执行模型。
13. 视频拆解结果包含脚本、关键词、关键帧和结构，可选择性创建选题或回流脚本、分镜、知识与资产，并保留来源和版本证据。
14. 批次内每条内容都能回溯选题、采用脚本、确认分镜、知识快照和输出资产。
15. 内容库可按全部、视频、图片、音频、文档筛选，并能继续按用途、来源和状态细分。
16. 六个媒体工具具备权利确认、状态、取消、失败、重试和输出入库路径，且不宣称绕过平台保护。

## 15. 当前原型边界

`docs/prototypes/` 下的本地交互原型用于验证信息架构、视觉层级和交互心智。它必须明确标注演示数据，不修改生产 Runtime、数据库或真实接口。进入生产实现前，必须另立包含接口地址、请求方法、参数、返回、错误码、示例、迁移和测试的 implementation plan / spec。
