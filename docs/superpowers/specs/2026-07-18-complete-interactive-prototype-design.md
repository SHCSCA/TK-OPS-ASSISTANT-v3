# TK-OPS 完整交互原型设计规格

> **状态：已被取代。** 本规格保留为历史记录；当前设计真源为 `docs/superpowers/specs/2026-07-19-account-first-batch-content-prototype-design.md`。

**状态：** 用户已批准，可进入 Superdesign 原型生成  
**设计日期：** 2026-07-18 至 2026-07-19  
**设计工具：** Superdesign CLI 0.6.0 及其远程画布  
**目标平台：** Windows PC 桌面应用  
**生产代码边界：** 本规格与原型阶段不修改 `apps/desktop/src/`、`apps/py-runtime/src/`、数据库或 Runtime API

## 1. 设计结论

本原型采用“保留现有青紫品牌基因、渐进升级信息层级与交互体验”的方向，以专业制作驾驶舱为骨架，融合创作阶段引导与情境式 AI 副驾。

设计必须持续回答四个问题：

1. 当前正在处理哪个项目和对象。
2. 当前对象与后台任务处于什么状态。
3. 用户此刻最合适的下一步是什么。
4. 发生异常后如何诊断、恢复并继续。

本原型固定覆盖全局桌面壳、16 个正式页面和五条端到端流程。它只面向 PC 宽屏与 PC 紧凑窗口，不包含手机端、平板端或移动触屏布局。

## 2. 真源与冲突裁决

设计按以下顺序服从项目真源：

1. 产品范围、主链与页面树：`docs/PRD.md`。
2. 视觉语言、壳层与页面布局：`docs/UI-DESIGN-PRD.md`。
3. 路由、目录、模块与模型落点：`docs/ARCHITECTURE-BOOTSTRAP.md`。
4. 工程、安全、数据真实性与实现约束：`AGENTS.md`。
5. 当前界面复现：`apps/desktop/src/` 的真实 Vue、TypeScript 和 CSS 源码。

旧 UI 文档色值与当前代码令牌存在差异时，像素级基线与渐进升级方案均以当前代码令牌为准。产品称谓与页面名称以当前正式 16 页为准，不沿用旧后台口径。

## 3. 范围与非目标

### 3.1 范围

- 全局 `Title Bar + Sidebar + Content Host + Detail Panel + Status Bar` 壳层。
- 16 个正式页面的主要工作态、状态契约和跨页关系。
- Light / Dark 双主题的同构设计。
- `1600 × 1000` 宽屏与 `1100 × 760` 紧凑窗口；最低支持 `960 × 640`。
- 首启恢复、从零创作、导入重制、执行发布、长任务恢复五条流程。
- 加载、空、正常、错误、受限及长任务状态。
- 键盘效率、可访问性、动效与高 DPI 显示缩放。

### 3.2 非目标

- 不新增第 17 页或扩展订单、退款、商品、重 CRM、团队协作后台。
- 不设计手机端、平板端、移动端导航或触屏手势。
- 不制作假账号、假设备、假工作区、假浏览器实例或假执行绑定。
- 不展示伪造的播放量、成功率、趋势、收益或发布结果。
- 不绕过许可证、一机一码、工作目录初始化或 Runtime 健康检查。
- 不在原型阶段实现生产接口、数据库迁移、真实自动化、渲染或发布能力。

## 4. 全局交互架构

### 4.1 宽屏壳层

宽屏基准为 `1600 × 1000`：

- Title Bar：高度 `48px`，显示品牌、当前项目、当前页面、保存状态、Runtime / AI 状态、主题与窗口控制。
- Sidebar：展开宽度 `280px`，按正式产品阶段组织 16 页并标识当前页面、受限项和异常项。
- Content Host：弹性宽度，只突出当前页面主任务。
- Detail Panel：宽度 `360px`，根据当前选中对象展示属性、AI 建议、引用关系、绑定、日志或诊断。
- Status Bar：高度 `28px`，持续展示保存、连接、后台任务、渲染、发布与错误状态。

### 4.2 PC 紧凑窗口

紧凑基准为 `1100 × 760`，最低支持 `960 × 640`：

- Sidebar 收缩为 `64px` 图标栏，悬停或键盘聚焦时展示名称。
- Detail Panel 改为按需右侧抽屉，关闭抽屉不清除当前选中对象。
- 次要工具收纳到“更多”菜单，主操作、播放控制、保存和错误反馈必须保留。
- Status Bar 压缩次要文字，但后台任务与异常状态保持可见。
- 页面整体不产生横向滚动；时间线、表格、日志和媒体轨道使用局部滚动容器。

### 4.3 壳层行为

- 切换页面时保留当前项目、后台任务、页面筛选、选中对象和可恢复的滚动位置。
- 切换项目时隔离选中对象和页面临时状态，并显式提示仍在其他项目运行的后台任务。
- 点击脚本段落、镜头、轨道、资产、账号、绑定或任务后，Detail Panel 切换到同一对象上下文。
- 长任务不因页面切换、Detail Panel 关闭或窗口缩小而终止。
- 上游内容变化影响下游时先展示影响范围，不直接覆盖用户修改。

### 5.3 页面关系

正式创作主链固定为：

`Project -> Script -> Storyboard -> Timeline -> VoiceTrack -> SubtitleTrack -> RenderTask`

从零创作和视频导入拆解必须回到同一个 Project。AI 剪辑工作台是内容中枢，脚本、分镜、配音、字幕、资产和拆解结果都向其回流。账号、设备、自动化、发布、渲染与复盘从属于创作交付闭环，不形成另一套后台。

## 6. 五条端到端流程

### 6.1 首启与故障恢复

主路径：

`许可证激活 -> 一机一码确认 -> 工作目录初始化 -> Runtime 检测 -> FFmpeg / FFprobe 检测 -> AI Provider 检测 -> 创作总览`

交互要求：

- 许可证、工作目录和 Runtime 是阻断项，不允许跳过。
- AI Provider 未配置时允许进入受限状态，但依赖该能力的操作必须禁用并提供配置入口。
- 每一步展示当前状态、检测结果、耗时、错误摘要和下一动作。
- 修复后从失败节点继续，已完成步骤不重复执行。
- 技术详情默认折叠，用户界面不直接展示 traceback。

### 6.2 从零创作到发布

主路径：

`创作总览 -> 脚本与选题 -> 分镜规划 -> AI 剪辑工作台 -> 配音 -> 字幕 -> 渲染 -> 发布 -> 复盘回流`

交互要求：

- 每阶段显示完成度、阻断问题和推荐下一步。
- 跨页前自动保存；保存失败时阻止离开并提供重试。
- 上游变更先展示下游影响范围，再由用户确认同步。
- 渲染与发布保持独立状态，渲染成功不能伪装为发布成功。
- 复盘只接受真实发布结果；没有数据时展示空态和连接指引。

### 6.3 导入视频重制

主路径：

`选择真实文件 -> 媒体探测 -> 镜头切分 -> 音频 / 字幕识别 -> 结构分析 -> 结果校对 -> 合并到 Project -> AI 剪辑工作台`

交互要求：

- 导入前校验文件存在性、格式、可读性和工作区空间。
- 每个分析阶段独立展示状态、耗时、输出与错误。
- 只重试失败阶段，保留已完成结果。
- 合并前列出将创建或更新的 Script、Storyboard 和 Timeline 对象。
- 合并后高亮新增内容，保留来源和版本记录。

### 6.4 执行绑定与发布

主路径：

`Account -> DeviceWorkspace -> 浏览器实例 -> ExecutionBinding -> 发布预检 -> 执行 -> 真实回执`

交互要求：

- 未绑定、绑定失效或浏览器不可用时禁止启动发布。
- 预检逐项展示账号、素材、字幕、工作区和执行环境结果。
- 运行日志中的敏感信息默认脱敏。
- 结果必须来自真实回执；无法确认时标记为“待确认”，不得标记成功。
- 失败后保留预检与执行上下文，支持修复后重试。

### 6.5 长任务恢复

统一状态机：

`排队中 -> 运行中 -> 正在取消 / 失败 / 完成`

交互要求：

- Status Bar 展示全局进度，Detail Panel 展示阶段、日志和可执行动作。
- 取消前确认；取消超时进入可诊断状态，不从队列中静默消失。
- 失败时展示失败阶段、中文原因、重试范围和日志入口。
- 重试默认从最小失败范围继续，不重复成功阶段。
- 完成后刷新相关页面缓存、任务队列和全局状态。

## 7. 页面与任务状态契约

### 7.1 页面状态

| 状态 | 视觉与内容 | 必须提供的动作 |
| --- | --- | --- |
| 加载中 | 保持稳定骨架，使用局部 Skeleton，不清空已知上下文 | 取消加载或返回 |
| 空状态 | 说明缺少的对象、原因及影响，不展示模拟数据 | 创建、导入或配置的唯一主入口 |
| 正常状态 | 展示真实对象、保存状态和当前主任务 | 编辑、保存、继续下一阶段 |
| 错误状态 | 展示中文摘要、影响对象和诊断入口 | 重试、修复配置、查看日志 |
| 受限状态 | 保留可浏览内容，明确禁用依赖能力 | 激活许可、连接 Runtime 或配置 Provider |

### 7.2 保存状态

- 未修改：不持续占用注意力。
- 有未保存修改：Title Bar 与页面操作区同时提示。
- 保存中：使用短状态反馈，禁止重复提交。
- 保存失败：阻止危险离开，保留编辑内容并提供重试。
- 需要同步：上游版本变化时展示影响范围，由用户确认刷新。

### 7.3 连接状态

- Runtime 在线：不突出展示，只保留可查询状态。
- Runtime 重连中：Status Bar 显示重连，页面保留最后已知数据并禁用写操作。
- Runtime 离线：页面级错误说明影响范围，提供重新连接与诊断。
- WebSocket 断线：自动重连，恢复后补拉任务最终状态，避免漏报完成或失败。

## 8. 反馈、日志与错误恢复

反馈层级固定为：

1. 字段级：紧贴输入项，说明格式、范围或依赖约束。
2. 对象级：显示在对应脚本段落、镜头、轨道、资产或任务卡片上。
3. 页面级：用于首屏加载失败、Runtime 不可用或项目损坏。
4. Toast：只反馈短暂结果，不承载必须处理的信息。
5. Detail Panel：承载诊断、影响范围、日志与恢复动作。
6. Status Bar：承载持续连接、保存和后台任务状态。
7. 确认弹窗：只用于不可逆覆盖、取消任务、删除引用对象等高风险动作。

统一恢复链为：

`发现错误 -> 中文摘要 -> 受影响对象 -> 技术详情折叠区 -> 推荐修复 -> 重试 -> 状态刷新`

日志至少记录时间、操作、对象、阶段、耗时、Provider 或运行版本、失败原因和关联任务。日志不得泄漏密钥、令牌、完整账号凭据或未脱敏路径信息。

## 9. Runtime 与数据真实性

- 所有原型动作按真实 Runtime HTTP / WebSocket 心智设计，不在 UI 层拼接业务规则。
- 成功信封为 `{ "ok": true, "data": ... }`，失败信封为 `{ "ok": false, "error": "..." }`。
- HTTP 提供当前结果，WebSocket 提供长任务状态；重连后必须补拉最终状态。
- 数据变化后同步刷新当前对象、依赖对象、缓存、队列和全局状态。
- 原型中的示例内容使用“未命名项目”“尚未生成”“等待真实回执”等中性文字。
- 不展示看似真实的播放量、收益、发布成功率、增长曲线或设备绑定结果。

## 10. 视觉设计系统

### 10.1 视觉定位

专业、克制、有创作氛围的 AI 视频制作台。保留现有品牌，避免传统经营后台、霓虹堆叠和无意义玻璃拟态。

### 10.2 色彩裁决

- Light 主色：`#0097A7`。
- Light AI 辅色：`#5E17EB`。
- Dark 主色：`#00BCD4`。
- Dark AI 辅色：`#7000FF`。
- 青色用于主操作、选择、焦点与执行进度。
- 紫色只用于 AI 能力、生成内容、智能建议和版本标识。
- 成功、警告、错误使用独立语义色，不能由青紫色替代。
- Dark 主题重新校准表面、边界与文字对比度，不机械反转 Light 主题。

### 10.3 排版与密度

- 中文使用 HarmonyOS Sans SC 或系统无衬线字体；英文与数字使用 Inter。
- 时间码、任务 ID、路径和日志使用等宽字体。
- 采用 `4px` 基础网格，保持专业密度并留出清晰层级。
- 文案使用中文行动语言，避免开发者占位、模糊状态和过度英文。

### 10.4 表面与组件状态

- 页面背景、工作区、浮层和选中对象形成四级表面层级。
- 卡片默认弱边框与低阴影；选中对象使用细青色描边和轻微外发光。
- AI 建议使用紫色边缘或小面积标识，不整块染紫。
- 按钮固定为主要、次要、幽灵、危险四种语义。
- Hover、Focus、Pressed、Disabled、Loading 与 Error 状态必须完整。
- Light / Dark 共用结构、间距和交互，只切换语义令牌。

## 12. PC 布局、效率与可访问性

### 12.1 视口与缩放

- 宽屏：`1600 × 1000`。
- 紧凑：`1100 × 760`。
- 最小：`960 × 640`。
- 检查 Windows `100%`、`125%`、`150%` 显示缩放。
- 不创建手机、平板或触屏移动端设计。

### 12.2 可调整区域

- 时间线、播放器、素材区和 Detail Panel 可按职责调整尺寸。
- 尺寸偏好通过统一配置总线记忆，不由页面各自持久化。
- 紧凑窗口优先保留主操作、播放、保存与错误；次要动作进入“更多”。

### 12.3 快捷键

- `Ctrl + K`：全局命令与项目内搜索。
- `Ctrl + S`：保存当前对象。
- `Ctrl + Z / Ctrl + Y`：撤销与重做。
- `Space`：播放器播放或暂停。
- `Esc`：退出聚焦态、关闭抽屉或弹窗。
- 方向键：时间线微调；`Shift` 扩展选择。
- 输入框获得焦点时避免全局快捷键冲突。

### 12.4 可访问性

- 所有主要操作可由键盘完成，焦点顺序与视觉布局一致。
- 焦点环清晰，状态不能只依赖颜色表达。
- 错误、成功、排队和禁用同时使用图标、文字和颜色。
- 文本、图标和状态色满足桌面界面对比度要求。
- 尊重系统减少动态效果设置。
- 时间线与日志允许放大文字而不破坏主布局。

## 13. 动效规则

- 即时反馈：`80–120ms`。
- 常规状态切换：`160–220ms`。
- Detail Panel、抽屉和局部重排：`240–320ms`。
- 长任务使用真实连续进度或明确的不确定进度，不播放装饰性无限循环。
- 强表现动效只用于首启引导、AI 生成完成和关键创作转场。
- 减少动态效果开启后取消位移、缩放和背景运动，但保留状态变化。
- 动效不得影响时间线拖动、播放、滚动和输入响应。

## 14. Superdesign 原型执行方案

### 14.1 生成前置

1. 每次设计命令前运行 `npx --yes @superdesign/cli@latest --version`。
2. 若命令返回认证错误，运行同一 CLI 的 `login`，成功后重试。
3. 重新读取 `.superdesign/init/` 六份文件和本规格。
4. 写入 `.superdesign/design-system.md`，作为所有草稿唯一视觉约束。
5. 创建 `.superdesign/tmp/` 用于组件 HTML，并确保该目录被 `.gitignore` 忽略。

### 14.2 当前界面基线

- 创建 Superdesign 项目并记录 CLI 返回的 Canvas URL。
- 以当前 AI 剪辑工作台为锚点进行像素级复现，不先做视觉优化。
- 递归提供 `pages.md` 所列页面依赖、全局主题和设计系统上下文。
- `AppShell.vue` 超过 1000 行，仅传入真实渲染相关区间，优先使用模板 `1:108` 与样式 `824:1121`，避免无关上下文。
- 复用现有 `TkopsBrandMark` 和真实图标，不使用替代品牌资产。

### 14.3 两个同方向分支

- 分支 A“精密制作驾驶舱”：更高信息密度、更稳定多栏、更强时间线与任务可见性。
- 分支 B“引导式制作驾驶舱”：保持专业骨架，强化阶段进度、推荐下一步和异常恢复。
- 两个分支只比较层级、密度和引导强度，不改变 16 页、模型、路由或产品定位。
- 通过 Canvas 与 Preview 链接让用户选择锚点；未选择前不扩展全量页面。

### 14.4 完整页面扩展

锚点批准后使用 `execute-flow-pages` 分两批生成：

- 第一批 10 页：首启与许可证向导、创作总览、脚本与选题、分镜规划、AI 剪辑工作台、视频拆解、配音、字幕对齐、资产、账号管理。
- 第二批 6 页：设备与工作区、自动化执行、发布、渲染与导出、复盘与优化、AI 与系统设置。

每个页面使用统一壳层、组件、状态语言和双主题，并支持 PC 宽屏与紧凑窗口。AI 剪辑工作台、任务队列、Detail Panel 和 Status Bar 必须分别检查两个 PC 视口。

### 14.5 画布组织

1. 当前界面像素级基线。
2. 分支 A 与分支 B。
3. 最终设计系统与共享组件。
4. 正式 16 页。
5. 五条核心流程与关键异常状态。

每次自然评审节点返回 CLI 输出中的 Canvas URL 和 Preview URL，不手工拼接服务端链接。

## 15. 原型交互清单

原型必须可演示以下行为：

- 使用 Sidebar 在 16 页之间导航并保持当前 Project。
- 选择、恢复或创建项目，并进入推荐下一阶段。
- 选择脚本段落、镜头、轨道、资产、任务、账号或绑定，打开对应 Detail Panel。
- 展开 AI 建议，预览影响范围，确认或取消。
- 触发保存、保存失败、重试和需要同步状态。
- 触发长任务的排队、运行、取消、失败、重试和完成状态。
- 展开中文错误摘要、技术详情和日志入口。
- 完成修复后刷新相关对象、缓存、队列和全局状态。
- 切换 Light / Dark 主题。
- 调整为宽屏或 PC 紧凑窗口并保持主任务可用。
- 对删除引用对象、覆盖版本、取消任务等高风险动作进行确认。

## 16. 验收标准

### 16.1 完整性

- 全局壳与 16 个 Route ID 全部出现且名称一致。
- 五条核心流程均能从入口走到明确终点。
- 所有页面定义加载、空、正常、错误和受限状态。
- AI、拆解、渲染、发布与自动化额外定义排队、运行、取消、失败、重试和完成。

### 16.2 一致性

- AI 剪辑工作台保持产品中枢地位。
- 页面共享同一设计系统、壳层、状态语言和错误恢复模式。
- Light / Dark 只切换语义令牌，不产生结构漂移。
- 当前代码色值、品牌标记和图标得到复用。

### 16.3 真实性与安全

- 不出现假业务数字、假执行结果或假对象绑定。
- 无真实数据时使用中性空态或引导态。
- 许可证、工作区、Runtime 与真实绑定门禁不可绕过。
- 长任务始终具备超时表达、失败提示、日志与重试路径。

### 16.4 PC 体验

- `1600 × 1000` 和 `1100 × 760` 下无错位、遮挡或页面整体横向滚动。
- 最小 `960 × 640` 下主操作、保存、播放与异常反馈仍可用。
- 键盘焦点、快捷键、对比度和减少动态效果行为明确。
- 不包含任何手机端、平板端或移动触屏适配。

## 17. 用户反馈校正：低噪音本地交互原型

2026-07-19 用户否决首轮两个锚点方案，原因是界面文字过多、状态与说明重复、视觉噪音过高，并明确要求提供本地可交互的原型设计稿。本节覆盖前文中与“高信息密度”或“持续展示全部状态”冲突的内容。

### 17.1 视觉减法

- 删除常驻面包屑、介绍段落、上下文 Chip 阵列、四联说明卡和重复状态文字。
- 页面头压缩为单行对象栏，最多保留三个高频动作；其余动作进入图标工具栏或“更多”。
- Sidebar 默认折叠，Detail Panel 默认关闭；只有对象选择、诊断或错误恢复触发时展开。
- 预览舞台与时间线成为唯一主视觉，资产与属性仅承担辅助职责。
- 默认状态使用图标、状态点、Tooltip 和短标签；完整说明通过渐进披露出现。

### 17.2 状态完整性

- 减少文字不等于删除状态。加载、空、正常、错误、受限和长任务状态仍必须可发现、可恢复、可追踪。
- 同一状态只在一个固定区域表达；错误摘要保持一句，技术详情、影响范围和日志按需展开。
- 空状态最多一条短句和一个主动作，不使用多张解释卡填充界面。

### 17.3 本地交付

- 在 `docs/prototypes/tk-ops-interactive/` 生成模块化静态原型，不写入生产路由或 Runtime 链路。
- 原型使用本地 HTML、CSS 和 JavaScript，可通过本地静态服务器启动。
- 至少支持 Sidebar 导航与折叠、Light / Dark、对象选择、Detail Panel、播放 / 暂停、时间线片段选择、任务状态切换、错误展示与恢复。
- 覆盖 `1600 × 1000`、`1100 × 760` 和最低 `960 × 640` 的 PC 窗口；不设计手机端。
- 使用 Playwright 验证关键交互、控制台错误和两个主要 PC 视口。

## 18. 设计完成后的交接

本规格批准后才进入 Superdesign 项目、基线和分支生成。用户在画布选择锚点后，才扩展 16 页和五条流程。原型批准后若进入生产实现，必须另行编写实现 plan / spec，并补充前后端接口地址、方法、参数、返回信封、错误码与示例；本设计规格不授权直接改动生产代码。
