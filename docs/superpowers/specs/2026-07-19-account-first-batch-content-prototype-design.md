# TK-OPS 账号优先批量内容工作区交互原型设计规格

**状态：** 已完成 Superdesign 与本地原型实现  
**日期：** 2026-07-19  
**目标平台：** Windows PC 桌面应用，不包含手机端、平板端或触屏适配  
**选定视觉：** 方案 1「极简生产台」  
**生产代码边界：** 不修改 `apps/desktop`、`apps/py-runtime`、数据库或真实接口

## 1. 设计结论

本原型验证“账号是整个工作区边界”的新产品心智。用户在 Sidebar 左下角切换账号后，定位、知识库、计划、批次、内容库、发布和复盘全部同步切换。原型不再展示 AI 剪辑工作台或手动多轨时间线。

选定方向使用深海军蓝 Sidebar、浅灰主画布、白色内容表面、青色阶段与品牌状态、紫色唯一主动作。首屏以阶段流、批次表格和异常列表为主，减少长说明、统计卡和重复标签。

## 3. 范围

### 3.1 必须实现

- 七入口账号级 Sidebar。
- Sidebar 底部系统设置和左下角账号切换器。
- 工作台、定位与知识、内容计划、批量生产、内容库、发布、复盘七个可切换视图。
- 当前账号标题、健康状态和“新建批次”主动作。
- 六阶段生产流：选题、脚本、分镜、生成、合成、待发布。
- 当前批次表格、异常列表和恢复动作。
- 账号切换、搜索账号和账号隔离演示。
- 新建批次、阶段筛选、异常重试、批次取消 / 恢复演示。
- 成片预览、镜头级重生成和版本选择，不出现时间线。
- Light / Dark 主题、宽屏与紧凑 PC 布局。
- 加载、空、正常、错误、取消、重试和成功反馈。

### 3.2 不实现

- 生产 Runtime、真实数据库、真实 Provider、真实发布或自动化。
- 手机端、平板端、触屏布局。
- AI 剪辑工作台、手动多轨时间线或专业剪辑工具。
- 订单、商品、收益、团队协作、经营大屏或高风险环境伪装。

## 4. 原型数据与真实性

原型使用两个明确标注的演示账号，数据只用于验证隔离：

- `镜头 A`：中文 AI 工具讲解定位。
- `Focus Lab`：英文效率与桌面工作流定位。

页面顶部持续显示“演示原型”。所有批次、来源和任务均使用演示语义，不表示真实平台结果。发布成功态只演示交互结构，并明确写为“演示回执”；生产版本必须由真实 Runtime 回执替换。

账号数据必须按对象分组，禁止通过切换后继续复用同一数组造成残留。切换时先进入 `switching`，清空可见选择，再加载目标账号工作区。

## 5. 全局布局

### 5.1 宽屏 `1440 × 900`

- Sidebar：`248px`，深海军蓝。
- Top Bar：`64px`。
- Content Host：浅灰 Canvas，水平内边距 `30px`。
- Optional Detail Panel：`360px`，只在选中对象时出现。
- 主内容纵向顺序：阶段流、当前批次、待处理异常。

### 5.2 紧凑 `1180 × 760`

- Sidebar：`76px` 图标栏，悬停或聚焦显示提示。
- 账号切换器只显示头像和状态点。
- Top Bar 隐藏重复账号副标题。
- 阶段流局部滚动。
- 批次表格隐藏更新时间等次要列。
- Detail Panel 以覆盖式抽屉呈现。

### 5.3 最小 `960 × 640`

- 保持 PC 图标 Sidebar，不切换手机导航。
- 主动作、账号切换、阶段、批次状态和异常恢复仍可访问。
- 页面整体不得横向溢出。

## 6. 工作台

### 6.1 Top Bar

- 左侧：`工作台`，下方或同排显示当前账号。
- 右侧：Runtime 状态、真实工作区状态的演示占位和紫色“新建批次”。
- 页面状态为错误或切换中时，健康状态必须同步变化。

### 6.2 阶段流

节点固定为选题、脚本、分镜、生成、合成、待发布。点击阶段筛选下方批次；再次点击当前阶段恢复全部。节点展示阶段名和低噪音状态，不显示大数字。

### 6.3 批次表格

列为批次、阶段、进度、更新时间、动作。默认按更新时间排列。每行只显示一个主动作；其余动作通过更多菜单或详情提供。

状态：

- 运行中：青色进度与“查看”。
- 排队中：中性进度与“详情”。
- 失败：危险色细线与“重试”。
- 完成：成功状态与“预览”。
- 待发布：紫色轻标识与“去发布”。

### 6.4 异常列表

异常按阻断程度排序。每条显示内容或批次、短原因、影响和一个恢复动作。点击行打开 Detail Panel；点击重试进入 Running，短延迟后演示成功或恢复状态。

## 7. 账号切换

1. 点击左下角账号区域，弹出向上展开的账号菜单。
2. 搜索框实时过滤账号名称和定位短标签。
3. 点击目标账号后关闭弹层，进入约 `450–650ms` 的切换态。
4. 清空阶段筛选、选中批次、Detail Panel 和临时搜索。
5. 更新 Sidebar 账号、Top Bar、所有页面数据和任务视图。
6. 显示“已切换到…”短 Toast。

若当前存在未保存的定位编辑，先显示确认 Dialog：保存并切换、放弃并切换、取消。

## 8. 新建批次

Dialog 只包含：

- 批次名称。
- 内容目标。
- 生成数量。
- 模板。
- 素材来源。
- 发布节奏。

高级参数折叠。提交后按钮进入 Running，创建一条当前账号范围的新批次并显示 Toast。校验失败就地提示；演示异常可触发页面级错误与重试。

## 9. 定位与知识

- 顶部显示一句定位摘要、版本和“编辑定位”。
- 来源以列表显示类型、名称、索引状态、更新时间和动作。
- 支持演示导入来源、更新索引、查看引用、禁用来源和回退版本。
- 索引失败或来源过期就地显示恢复入口。
- 规则、禁用词、钩子和 CTA 通过标签页或折叠区展示。

## 10. 内容计划

- 显示内容支柱、选题矩阵和紧凑周节奏。
- 支持多选选题后创建批次。
- 空态只显示“建立本周计划”主动作。
- 不使用复杂甘特图、看板或经营指标。

## 11. 批量生产

- 顶部显示批次、阶段、整体进度、取消和失败重试。
- 内容变体表格支持全部、异常、待确认、已完成筛选。
- 选择内容后打开成片预览 Detail Panel。
- Detail Panel 支持切换版本、重生成镜头、重新合成和确认成片。
- 所有生成动作显示 Loading、成功或失败反馈。
- 不得出现片段拖拽、轨道、剪刀、磁吸或时间码编辑器。

## 12. 内容库、发布与复盘

### 内容库

用紧凑列表和缩略图展示成片、脚本、素材、模板和版本。缺失文件显示修复入口，空态引导导入或归档已完成批次。

### 发布

显示当前账号和执行绑定、预检清单、待发布任务、失败和演示回执。修复前阻断发布；失败任务保留上下文和重试。

### 复盘

显示内容结果、证据和可执行建议。建议只能回流到定位、知识或计划，并需要用户确认。没有真实数据时使用中性空态。

## 13. 主题与令牌

设计令牌以 `.superdesign/design-system.md` 为唯一 Superdesign 上下文。原型 CSS 必须使用 Variables，并提供 Light / Dark 同构结构。

关键颜色：

- Sidebar `#0D1726`。
- Canvas `#F5F7FA`。
- Brand cyan `#13B8C8`。
- Primary violet `#6C4CF1`。
- Danger `#D94B55`。

## 14. 状态与反馈

页面状态：`loading | empty | ready | error | restricted`。

任务状态：`queued | running | cancelling | failed | completed`。

统一恢复链：

`中文摘要 -> 影响对象 -> 推荐修复 -> 重试 -> 刷新 -> 成功反馈`

日志使用原型内统一 logger，异常必须捕获、记录并转换为可见中文反馈。原型配置通过单一配置对象管理，不允许组件散落保存。

## 15. 模块化文件边界

本地原型新建在 `docs/prototypes/tk-ops-account-workspace/`，使用 Vite + React Starter，旧原型保留为历史参考。新原型按以下边界拆分：

```text
src/
├── app/
├── components/
├── data/
├── config/
├── pages/
├── state/
├── styles/
└── utils/
```

禁止把全部状态、页面、交互和样式堆进单个文件。现有旧静态脚本可保留为历史文件，但新入口不得引用它们。

## 16. Superdesign 执行

1. 读取 `.superdesign/init/` 六个上下文文件。
2. 使用当前旧原型和真实设计令牌生成像素级基线。
3. 只创建一个“极简生产台”迭代分支。
4. 迭代 Prompt 必须包含本规格、`.superdesign/design-system.md`、当前 CSS 和用户原话“好”。
5. 读取设计 JSON 后再实现本地原型。

## 17. 设计 QA

实现后使用同一视口把选定视觉参考与实现截图放进同一对比画面。按以下优先级修复：

- P0：布局错位、遮挡、不可用交互、账号数据残留。
- P1：Sidebar、Top Bar、阶段流、批次表格、颜色和间距明显不一致。
- P2：细节对齐、字体、图标、Hover、动效和紧凑窗口问题。

结果记录到原型根目录 `design-qa.md`。P0 / P1 必须清零，P2 只允许记录不影响使用的已知差异。

## 18. 验收标准

1. 首屏文字和视觉噪音显著低于旧原型。
2. 左下角可搜索切换账号，切换后所有七页内容严格更换。
3. 七入口导航和系统设置边界清晰。
4. 可创建批次、筛选阶段、处理异常、预览版本和演示发布预检。
5. 不出现 AI 剪辑工作台或多轨时间线。
6. Light / Dark、`1440×900` 和约 `1180×760` 可用。
7. Loading、Empty、Ready、Error、Retry、Cancel 和 Success 状态有可见反馈。
8. 本轮不修改生产应用、Runtime、数据库或真实接口。
