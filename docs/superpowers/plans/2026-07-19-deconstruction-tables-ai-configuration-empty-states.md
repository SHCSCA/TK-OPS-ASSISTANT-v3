## 1. 背景与问题判断

本轮反馈暴露了三个结构问题：

1. 视频拆解已经具备脚本、关键词、关键帧和结构数据，但展示仍偏自定义卡片，跨行比较和批量选择效率不足；内容结构缺少整条视频的特点总结和可复用标签。
2. 系统 AI 设置只展示 Provider Profile。添加 Provider 是无后续动作的演示按钮；模型、产品能力、Prompt 和账号 Recipe 之间没有可配置映射。
3. 原型用一个全局页面空态代替真实无数据状态，且默认引导创建批次，不符合“定位 / AI 就绪 -> 选题 -> 脚本 -> 分镜 -> 生产”的前置顺序。

这些问题应在现有账号优先、低噪音、PC 工作台框架内增量修复，不新增主导航，不恢复剪辑工作台，不扩展为团队后台。

## 2. 本轮目标

1. 将视频拆解四类结果统一为易读、可比较、可选择的表格体系。
2. 为内容结构补充视频特点总结、节奏与叙事标签，并保留证据可追溯性。
3. 打通 Provider 新增、模型管理、能力路由、Prompt 模板和 Recipe 继承的原型配置闭环。
4. 用真实数据条件推导页面级空态，覆盖首次空、筛选为空、前置不足、能力受限和等待结果。
5. 保持 Light / Dark、`1440×900`、约 `1180×760` 与 `960×640` 紧凑 PC 窗口可用。
6. 吸收 Pixelle-Video 已验证的生成流水线、能力契约与模板思路，但按 TK-OPS 的账号隔离、配置总线、版本和审核边界重构。

## 3. 产品与交互决策

### 3.1 视频拆解结果

保留四个标签页，但每个标签页使用真实语义表格，不强迫四类数据使用完全相同的列。

#### 脚本文案表

| 列 | 内容 |
| --- | --- |
| 选择 | 单段回流选择 |
| 时间段 | 开始与结束时间 |
| 脚本文案 | 最大宽度，允许两至三行阅读 |
| 段落作用 | Hook、方法、证据、CTA 等 |
| 置信度 | 高、中、低与数值证据 |

#### 关键词表

| 列 | 内容 |
| --- | --- |
| 选择 | 单词或词组回流选择 |
| 关键词 | 关键词正文 |
| 分类 | 主题、人物 / 对象、视觉、动作、语气 |
| 权重 | 百分比与轻量条 |
| 命中 | 次数 |
| 证据 | 可点击时间点 |

#### 关键帧表

| 列 | 内容 |
| --- | --- |
| 选择 | 真实帧回流选择 |
| 预览 | 真实缩略图，不生成伪缩略图 |
| 时间点 | 帧时间 |
| 镜头作用 | 结果前置、步骤切换、验证等 |
| 画面摘要 | AI 分析或人工补充 |
| 可复用方向 | 分镜参考、封面、图片资产 |

没有真实帧时继续使用稳定空态，不渲染空表格。

#### 内容结构表

表格上方保留比例条，并增加：

- 一至两句“视频特点总结”。
- `featureTags`：例如结果前置、步骤教学、证据闭环、短 CTA、快节奏口播。
- 总时长、结构段数量和主要叙事类型的紧凑摘要。

表格列固定为选择、结构段、时间、时长占比、作用、对应文案、证据关键词。

### 3.2 AI 配置闭环

系统设置仍只保留“AI 能力 / Runtime 与工作区 / 日志与诊断”三个一级分区。AI 能力内部新增三个低高度二级分区：

```text
Provider | 模型与能力 | Prompt 模板
```

#### Provider

- “添加 Provider”打开可完成的宽屏居中向导。
- 步骤：连接类型 -> 地址与凭据引用 -> 网络与并发 -> 发现 / 手动添加模型 -> 测试并保存。
- 覆盖字段校验、重复 Provider、连接失败、取消、重试和保存成功反馈。
- 凭据只显示遮罩或安全存储引用，不把真实密钥写入演示数据、日志或页面状态。

#### 模型与能力

- 一个 Provider 可配置多个可调用模型。
- 每个模型展示模型 ID、显示名、Provider、启用状态、上下文或媒体限制和能力声明。
- 能力路由按产品能力展示：选题、脚本生成、脚本优化、分镜、视频拆解、转写、文生图、文生视频、图生视频、TTS、字幕、Embedding。
- 每项能力配置主模型、回退模型和 Prompt Profile；缺失项显示阻断原因与唯一修复动作。

#### Prompt 模板

- Prompt 按产品能力管理，不按页面散落保存。
- 字段至少包含名称、能力、系统提示词、任务模板、变量、输出格式 / Schema、版本、状态和继承范围。
- 支持新建版本、复制、预览变量填充、设为系统默认和查看被哪些 Recipe / 能力路由引用。
- 保存前校验必需变量与输出格式；存在未保存正文时，切换模板、关闭详情或离开设置需触发守卫。

#### 配置继承

固定使用：

```text
系统 CapabilityRoute -> 账号 AccountAIRecipe 覆盖 -> 单次 ProductionBatch 覆盖
```

Provider 只负责连接；模型负责可调用实体；能力路由负责产品功能选哪个模型和 Prompt；Recipe 负责账号风格、模型覆盖、音色、成本与回退。

### 3.3 需要补充的领域对象

| 对象 | 职责 |
| --- | --- |
| `ProviderProfile` | 连接、凭据引用、网络、并发与健康 |
| `ModelProfile` | Provider 下的真实模型 ID、启用状态和基础限制 |
| `ModelCapability` | 模型声明支持的文本、图像、视频、音频模式及参数边界 |
| `PromptProfile` | 版本化系统提示、任务模板、变量、输出 Schema 与引用 |
| `CapabilityRoute` | 产品 AI 能力到主模型、回退模型和 Prompt 的系统映射 |
| `AccountAIRecipe` | 对 CapabilityRoute 的账号级覆盖及风格、成本、音色策略 |

### 3.4 空状态体系

空状态不再由一个全局文案覆盖全部页面。统一状态分类：

- `first_use`：账号或模块第一次使用。
- `no_data`：没有任何业务对象。
- `filtered_empty`：存在数据，但当前筛选无结果。
- `dependency_blocked`：缺少上游内容、采用版本、真实连接或 AI 能力。
- `waiting_external`：等待 Provider、平台回执或长任务。
- `restricted`：账号、工作区或能力暂不可用。

每个空态只显示标题、影响说明和一个主动作，必要的次级修复链接进入详情，不增加卡片墙。

页面主动作映射：

| 页面 | 空态主动作 |
| --- | --- |
| 工作台 | 完成账号设置；就绪后改为新建选题 |
| 定位与知识 | 建立定位或添加知识来源 |
| 脚本与选题 | 新建选题 |
| 分镜规划 | 返回脚本并采用；已有采用脚本时生成分镜 |
| 视频拆解 | 导入视频 |
| 批量生产 | 继续创作；有确认内容后创建批次 |
| 内容库 | 导入素材或从生产归档；筛选为空时清除筛选 |
| 媒体工具箱 | 选择工具创建第一个任务 |
| 发布 | 前往生产获取可发布成片 |
| 复盘 | 等待真实回执或检查连接 |
| AI 设置 | 添加 Provider、配置模型或补齐能力路由 |

原型设置页保留状态演示入口，但“空态”改为可跨页面浏览的零数据场景，不再直接用全局 `StatePanel` 替换所有页面。

## 4. Pixelle-Video 吸收决策

本轮以仓库当前 `main` 分支的 README、配置 Schema、标准流水线、资产流水线、能力元数据、进度模型和 WebUI 配置实现为证据。吸收的是可复用的产品与架构机制，不复制 Streamlit 页面结构，也不照搬凭据、日志和单工作区边界。

### 4.1 直接采用

| Pixelle-Video 机制 | TK-OPS 采用方式 |
| --- | --- |
| 主题生成与固定脚本两种输入 | 保留“AI 主题”和“固定脚本”，固定脚本支持按段落、行、句子拆分为镜头草稿 |
| 标准线性流水线 | 采用“内容 -> 视觉规划 -> 镜头资产 -> TTS -> 字幕 -> 合成 / BGM -> 预览”的节点化执行模型 |
| 直接 API、ComfyUI、RunningHub 统一为媒体能力 | 统一进入 Provider 适配层和 `CapabilityRoute`，页面只读取标准化能力和健康状态 |
| 模型能力元数据驱动参数 | 时长、比例、分辨率、输入模态、原生音频、水印和并发只在模型声明且适配器已支持时显示 |
| 结构化进度事件 | `GenerationStep` 记录阶段、总体进度、镜头进度、动作、附加信息和最小重试范围 |
| Prompt 风格前缀与模板预览 | 形成版本化 `PromptProfile`、视觉风格配置和合成模板预览 |
| 已有素材分析与脚本匹配 | 当前账号资产先经分析，再由分镜绑定真实资产并保留来源证据 |
| 历史记录和批量生成 | 继续落在账号级 `ProductionBatch`、`BatchEntry`、任务日志和内容库中 |

### 4.2 适配吸收

| 原机制 | TK-OPS 适配 |
| --- | --- |
| 每句旁白生成一张图或一段视频 | 改为每个已确认分镜镜头生成媒体，旁白句子不直接决定业务模型 |
| 全局 `prompt_prefix` | 改为系统 `PromptProfile` -> 账号 `AccountAIRecipe` / `BrandKit` -> 批次覆盖，并记录版本 |
| HTML 模板与自定义参数 | 改为受控 `CompositionTemplateProfile`，包含类型、画幅、参数 Schema、预览和兼容能力 |
| 一键全自动生成 | 保留自动执行，但脚本采用、分镜确认、权利确认和发布预检仍是明确门槛 |
| Provider 原始配置直接作用于页面 | 改为系统 Provider、安全凭据引用、模型档案、能力路由和账号配方分层 |
| 模型宣称能力 | 区分“供应商声明能力”和“当前适配器已接入能力”，未验证能力不能成为默认路由 |
| 失败后自动改写 Prompt | 改为可见的安全重试建议；必须保留原 Prompt 版本、原因和用户确认，不静默改变内容意图 |
| 素材流水线自动修正或回退资产 | 改为可见的镜头素材匹配置信度、候选资产和人工确认，不静默替换错误资产 |

### 4.3 当前不采用

- 不采用 Streamlit 三栏页面和单个全局项目状态；TK-OPS 保持账号级桌面工作区。
- 不把动作迁移、参考视频生成、数字人和声音克隆加入 V1 默认路径。
- 不在普通设置页暴露 ComfyUI 原始工作流 JSON、命令行或供应商私有参数。
- 不记录完整 Prompt、私密文件路径、密钥或请求正文；日志只保存安全摘要、版本和引用。
- 不允许模型营销能力直接视为可用；没有适配器支持、契约来源或验证状态时只能显示为“未接入”。
- 不绕过脚本 / 分镜版本确认、素材权利确认、账号隔离和发布真实回执。

## 5. 额外发现与纳入范围

1. AI 能力配置完成度必须回传脚本、分镜、拆解和生产入口；缺失模型或 Prompt 时禁用执行，并显示可跳转的修复提示。
2. 当前工作台空态直接创建批次的顺序错误，需改为基于账号就绪度选择“完成账号设置”或“新建选题”。
3. `Provider Profile`、`Recipe` 等技术名词可保留，但中文标题应成为主层级，减少中英文混排造成的理解成本。
4. 表格需要键盘可达、可见焦点、表头语义、行选择标签和局部滚动；不能依赖整行颜色表达选择状态。
5. `ModelCapability` 必须同时记录供应商声明能力、适配器已接入能力、契约验证状态、来源和已知限制；产品只可路由到已接入且已验证的交集。
6. 固定脚本拆分、视觉风格、模板、TTS、BGM 和模型专属参数都必须进入版本化配置快照，不能只存在于向导临时状态。

## 9. 必须验证的主链

1. 拆解视频 -> 查看脚本表 -> 选择段落 -> 查看关键词证据 -> 查看结构总结与 Tag -> 预览回流影响。
2. 无真实关键帧 -> 显示稳定空态 -> 重新提取；有真实帧时展示缩略图表和可复用方向。
3. 添加 Provider -> 字段校验 -> 连接测试 -> 保存 -> 添加 / 发现模型 -> 声明能力。
4. 新建 Prompt -> 编辑系统提示与任务模板 -> 校验变量 -> 保存新版本 -> 绑定能力路由。
5. 能力路由缺失 -> 脚本或分镜动作被阻断 -> 跳转 AI 设置 -> 修复 -> 返回后动作恢复。
6. 切换零数据场景 -> 依次打开十个账号级页面 -> 每页显示符合前置条件的唯一主动作。
7. 有数据但筛选无结果 -> 清除筛选 -> 恢复数据；不得误导用户导入或新建业务对象。
8. 固定脚本 -> 选择段落 / 行 / 句子拆分 -> 形成镜头草稿 -> 绑定已验证媒体能力与模板 -> 查看逐镜头进度。
9. 模型宣称能力但适配器未接入 -> 参数不出现且路由不可用 -> 查看契约限制 -> 切换已验证模型。

## 10. 验收标准

| 维度 | 验收要求 |
| --- | --- |
| 拆解可读性 | 四类结果有明确表头、稳定列关系、轻量选择态和证据 |
| 内容结构 | 比例、整条视频特点总结、Tag 与结构段证据同时可见但不拥挤 |
| Provider | 添加按钮打开可完成向导，失败和成功均有稳定反馈 |
| 模型 | 模型可新增 / 发现、启停、声明能力并显示限制 |
| Prompt | 可按能力配置、版本化、校验变量并查看引用 |
| 能力路由 | 每个 AI 功能能追溯主模型、回退模型、Prompt 和继承来源 |
| 空状态 | 页面根据真实数据与依赖显示正确主动作，不再统一创建批次 |
| 低噪音 | AI 设置保持二级分区，不形成模型、Prompt 和 Provider 卡片墙 |
| 状态反馈 | 加载、空、正常、错误、受限、保存、失败和重试可见 |
| PC 适配 | 1440、1180、960 三档完成主要任务，无页面级横向滚动 |
| 工程边界 | 配置走统一配置总线，状态、数据、组件、样式和测试按职责拆分 |
| Pixelle 吸收 | 输入模式、能力契约、节点进度、视觉风格、模板和资产分析均有明确 TK-OPS 落点，且未引入其越界能力 |

## 11. 非目标与边界

- 本轮不接入真实 Provider、真实密钥或生产 Runtime。
- 不把 Prompt 原文写入执行日志；只记录安全摘要、版本和引用。
- 不新增主导航，不恢复剪辑工作台，不增加手机端适配。
- 不实现团队共享 Prompt 市场、计费后台或模型供应商商城。
- 不用伪关键帧、伪 AI 结果或假连接成功冒充真实状态。
- 不修改 `apps/desktop` 或 `apps/py-runtime`；本轮只完善本地交互原型与对应真源。
