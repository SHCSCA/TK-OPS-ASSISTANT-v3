# TK-OPS 完整交互原型设计计划

> **状态：已被取代。** 本计划保留为历史记录；当前执行真源为 `docs/superpowers/plans/2026-07-19-account-first-batch-content-prototype.md`。

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:brainstorming` 完成需求澄清与方案审批；使用 `Superdesign:superdesign` 生成和迭代原型。步骤使用复选框跟踪，本计划获批前不得生成设计稿、编写设计规格或修改生产代码。

**目标：** 在不改变 TK-OPS “AI 视频创作中枢”产品定位的前提下，为固定 16 页和全局桌面壳生成一套可在 Superdesign 画布审阅的完整交互原型，覆盖核心创作闭环、真实状态反馈、异常恢复、Light / Dark 双主题与宽屏 / 紧凑窗口。

**架构：** 以 `docs/PRD.md`、`docs/UI-DESIGN-PRD.md`、`docs/ARCHITECTURE-BOOTSTRAP.md` 和当前 Vue 实现为四层真源。先建立 `.superdesign/init/` 代码上下文和统一设计系统，再以当前 AI 剪辑工作台为像素级基线，分支探索视觉与交互方向；锚点方向获批后，按页面族扩展 16 页流程并逐批验收。原型只表达 Runtime 能真实支持或明确标注为空态 / 引导态的能力，不伪造业务结果。

**技术栈：** Superdesign CLI、Vue 3 + TypeScript 现有 UI 上下文、CSS Variables 设计令牌、Tauri 桌面布局契约、Markdown 设计规格。

## 1. 已确认的项目基线

- 产品固定为 Windows 本地优先的 `AI 视频创作中枢`，第一目标平台是 TikTok。
- 正式范围固定为 16 页，不新增第 17 个主路由，不回流订单、退款、商品、CRM 或团队后台。
- 创作主链固定为 `Project -> Script -> Storyboard -> Timeline -> VoiceTrack -> SubtitleTrack -> RenderTask`。
- 全局壳固定为 `Title Bar + Sidebar + Content Host + Detail Panel + Status Bar`。
- 当前 16 页 UI 和 Runtime 基础接线已存在；原型重点是统一“当前对象、当前状态、下一步动作、异常恢复”的用户心智，而不是制作脱离实现的概念稿。
- 现有前端采用青色主色、紫色 AI 辅色、Light / Dark 语义令牌和五级动效；设计规格阶段需裁决 UI 文档旧色值与当前代码令牌的差异。
- 计划启动时 `.superdesign/` 尚不存在；现已按批准计划完成六份初始化上下文。

## 2. 原型覆盖范围

### 2.1 全局壳与跨页交互

- Title Bar：当前项目、页面、Runtime、AI Provider、许可证、主题和窗口控制。
- Sidebar：五组正式导航、折叠态、项目上下文缺失态和紧凑窗口遮罩。
- Detail Panel：上下文属性、日志、版本、绑定、预检与诊断；紧凑窗口转 Rail / Focus。
- Status Bar：保存、同步、任务、AI、渲染、发布和错误状态的持续反馈。
- 全局反馈：Toast、确认弹窗、任务进度、可取消、失败重试、日志入口、空态和受限模式。

### 2.2 16 页页面族

1. 启动与总览：首启与许可证向导、创作总览。
2. 创作前置：脚本与选题、分镜规划、视频拆解。
3. 创作与媒体：AI 剪辑工作台、配音、字幕对齐、资产、渲染与导出。
4. 执行与治理：账号、设备与工作区、自动化、发布、复盘与优化。
5. 系统与 AI：AI 与系统设置。

### 2.3 必须可演示的核心流程

- 首启恢复：许可证激活 -> 目录初始化 -> Runtime / FFprobe / Provider 检测 -> 失败修复 -> 进入总览。
- 从零创作：总览 -> 脚本 -> 分镜 -> 剪辑工作台 -> 配音 -> 字幕 -> 渲染 -> 发布 -> 复盘回流。
- 导入重制：视频导入 -> 分阶段拆解 -> 局部重试 -> 回流脚本 / 分镜 / 时间线。
- 执行治理：账号 -> 真实工作区 / 浏览器实例 -> ExecutionBinding -> 发布预检 -> 任务回执。
- 长任务恢复：排队 -> 运行 -> 取消 / 失败 -> 日志诊断 -> 重试 -> 完成。

### 2.4 状态与视口

- 每个页面至少表达加载中、空状态、正常状态、错误状态。
- AI、拆解、渲染、发布、自动化页面额外表达排队、运行、取消、失败、可重试、完成。
- 原型仅面向 PC 桌面应用，不包含手机端、平板端或移动触屏布局。
- 桌面宽屏基准：`1600px` 及以上，多栏常驻。
- PC 紧凑窗口基准：`960px - 1199px`，Sidebar 折叠、Detail Panel 转 Rail / Focus、工具条压缩。
- Light / Dark 使用同一结构和语义，不制作两套互相漂移的页面。

## 5. 验收矩阵

| 维度 | 验收标准 |
| --- | --- |
| 产品范围 | 恰好 16 页；AI 视频创作中枢定位不漂移 |
| 主链连续性 | 脚本、分镜、时间线、配音、字幕、渲染、发布、复盘共享项目上下文 |
| 数据真实性 | 不展示无来源的真实感数字；缺数据时使用中性空态或引导态 |
| 交互状态 | 加载、空、正常、错误、运行、取消、重试、完成可见且可恢复 |
| 长任务 | 有归属、阶段、更新时间、日志、取消与重试 |
| 高风险动作 | 覆盖删除、覆盖、发布、批量执行等确认和撤销 / 恢复路径 |
| 全局一致性 | Shell、按钮、状态、文案、Detail Panel、Status Bar 行为一致 |
| 响应式 | 1600px+ 宽屏与 960-1199px 紧凑窗口均可完成主流程 |
| 主题与可达性 | Light / Dark 语义一致；状态不只依赖颜色；Reduced Motion 有降级原则 |
| 工程可落地 | 页面映射现有 Route ID、Runtime 能力和职责边界，可拆成后续实现任务 |

## 6. 主要风险与控制

- **范围过大：** 16 页不是一次无差别生成；先锁定壳层与锚点，再按 10 + 6 分批扩展。
- **视觉真源冲突：** UI 文档和当前 CSS 令牌存在色值差异；设计规格必须明确裁决，不允许生成时自行混用。
- **上下文过载：** 预先统计 `--context-file` 行数；超大文件只传真实渲染区间，遇到 400 继续收窄大文件区间，不用缺失上下文的泛化稿代替。
- **页面漂成后台：** 所有页面以“继续创作任务”为首屏优先级，禁止引入经营指标、CRM 或团队审批语义。
- **假业务结果：** 原型只使用中性示例、结构占位和状态说明；任何数字必须明确为演示结构而非真实数据。
- **原型与实现脱节：** 每个页面记录对应 Route ID、Runtime 资源前缀和状态来源；未实现能力必须标记依赖。
- **响应式被遗漏：** 紧凑窗口不是最后压缩；锚点阶段就验证 Sidebar、Detail Panel、工具条和时间线折叠策略。
