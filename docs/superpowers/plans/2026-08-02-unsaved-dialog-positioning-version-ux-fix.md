# P0-G 补丁：未保存决策与定位版本可读性修复计划

> 日期：2026-08-02  
> 状态：已完成，0.4.8 测试制品已验收  
> 类型：Desktop / Runtime / API 契约 / 测试的跨层缺陷修复  
> 产品边界：账号级定位与知识、不可变定位版本、真实 Runtime 数据  
> 目标版本：`0.4.8`（补丁版本）  
> 规划就绪度：95/100；外部 inspiration / reviewer 未挂载，按 `all-plan` 规则跳过外部评分

> 2026-08-08 验收补充：已外发的 `0.4.8` 免安装包根目录暴露内部 Runtime EXE。该问题属于本计划“Windows 测试包可直接交付”的验收缺陷，修复版本升为 `0.4.9`；根目录只保留 Desktop EXE，Runtime 收进内部资源目录，并增加制品结构门禁。

## 1. 问题与已确认原因

### 1.1 未保存弹窗按钮点击无效

`AccountWorkspaceLayout.vue` 将 `AccountUnsavedDecisionController.resolve` 直接作为 Vue 事件回调传递。该方法依赖类实例上的 `resolver`，脱离实例调用后会丢失 `this`，因此弹窗虽然正常发出 `cancel`、`discard`、`save` 决策，控制器却不能完成待处理 Promise。

现有测试直接调用控制器实例方法，没有真实点击三个按钮，因此没有覆盖组件到控制器的事件接线。

### 1.2 定位版本只显示 `v1`

当前列表 DTO 仅暴露 `version / status / summary / createdAt`，创建时的摘要又固定为“已配置 N 个内容支柱”。Desktop 只能显示泛化摘要和版本号，且当前没有获取单个版本详情的接口，也没有详情面板和基于历史版本预填编辑器的交互。

这与 `docs/UI-DESIGN-PRD.md` 中“显示定位简要摘要、当前版本和编辑定位”的要求不一致。

## 2. 成功定义

1. 未保存弹窗的“取消”“放弃并继续”“保存并继续”均能完成对应决策；处理期间不可重复提交，失败时有中文反馈和可追踪日志。
2. 当前定位卡片直接显示目标受众、核心内容方向和标签，不再只显示 `v1` 与数量。
3. 用户可从当前版本和历史版本进入详情，完整查看受众、内容支柱、语气、禁用主题、发布约束、状态与版本信息。
4. 用户可“基于此版本修改”，编辑器使用真实版本数据预填，保存后生成新的不可变版本，不静默覆盖已被内容任务引用的旧版本。
5. 新增详情接口、Desktop 调用和错误码写入唯一 API 文档，并通过账号隔离、空态、加载态、错误态和关键交互测试。
6. Desktop、Tauri 和 Python Runtime 统一显示 `0.4.8`；新测试包由该版本重新生成 manifest、build ID 与 SHA-256。

## 2.1 版本判定与长期规则

本次没有新增产品页面或不兼容契约，属于向后兼容的缺陷修复，因此由 `0.4.7` 升级为 `0.4.8`。

后续统一遵循 `docs/VERSIONING.md`：

- 兼容性缺陷修复升级 `PATCH`。
- 向后兼容的新功能升级 `MINOR`。
- 不兼容的产品、数据、API、许可证或执行协议变化升级 `MAJOR`。
- 一个交付批次包含多个缺陷时只升一次补丁号；已对外发出的测试包在代码变化后重新发包，必须再次升级补丁号。
- 根 `package.json` 是版本唯一真源，其他源码镜像由同步脚本维护；Runtime manifest 和 EXE 版本只能由真实构建生成，禁止手工伪改。

## 3. 产品与数据边界

- 定位版本继续采用不可变模型；“修改”在交互上表现为编辑，在数据上保存为 `vNext`。
- 不新增独立页面，详情使用“定位与知识”页内 Detail Panel / 抽屉，符合十三个页面容器边界。
- 不在组件内直接 `fetch`；所有请求通过 Runtime 适配层和账号知识 store。
- 不引入假业务结果。摘要从真实版本字段派生；旧版本在读取时兼容生成可读摘要，不要求用户重建数据。
- 不改变定位版本被脚本、分镜和批次引用时的版本追溯规则。

## 4. 交互方案

### 4.1 未保存决策

- Layout 使用具名、带类型的包装函数接收 `decide` 事件，再由实例调用 `resolve(decision)`，避免方法脱离实例。
- `save` 或 `discard` 执行期间三个按钮进入忙碌/禁用状态，防止双击产生并发切换。
- 保存失败时保留弹窗和当前工作区，展示统一中文错误；只有成功才继续原操作。

### 4.2 当前定位概览

当前卡片显示：

```text
面向：准备开拓海外市场的独立开发者
方向：产品拆解 · 增长实验 · AI 工作流
标签：#实操型  #数据驱动  #克制表达
当前版本：v1（使用中）
```

操作为“查看详情”和“编辑定位”。版本号保留为追溯信息，不再承担主要内容表达。

### 4.3 版本详情与修改

- 点击版本行或“查看详情”打开右侧详情面板。
- 详情按“目标受众 / 内容支柱 / 表达语气 / 禁用主题 / 发布约束”分组，空字段明确显示“未配置”。
- 使用中版本和草稿版本都可“基于此版本修改”。
- 编辑器标题显示“基于 vN 创建新版本”，主按钮显示“保存为 vN+1”。
- 保存成功后刷新版本列表并打开新版本详情；是否激活仍由显式“设为使用中”操作决定，避免无意切换生产基线。

## 5. 分阶段实施

### J0：验收用例先行

**目标**：把两个缺陷转成稳定复现用例。

**改动**：

- 增加 Layout 级测试，真实点击未保存弹窗三个按钮，不再只直接调用控制器。
- 增加定位版本详情接口和“基于版本修改”失败用例骨架。
- 固定账号切换、路由跳转和当前页刷新三种触发来源。
- 将版本同步脚本扩展到 Cargo lock，并让版本检查只校验正式版本镜像，历史 Changelog 与历史验收证据不被误判为漂移。

**验收**：新用例在修复前能准确失败，且不依赖 seed 伪造业务结果。

**回退点**：只回退新增测试，不改生产行为。

### J1：未保存弹窗闭环

**目标**：修复按钮无效并补齐并发与错误状态。

**改动**：

- 在 Account Workspace Layout 内增加稳定事件包装函数。
- 为决策控制器或对话框补充 `pendingAction` 状态，统一禁用、错误恢复和日志入口。
- 验证取消停留原页面、放弃清理脏状态后继续、保存成功后继续、保存失败后停留。

**验收**：三个真实按钮及三类导航来源全部符合决策语义，无未处理异常。

**回退点**：保留现有守卫协议，仅回退事件包装和忙碌态。

### J2：定位详情与语义摘要契约

**目标**：让 Runtime 提供账号隔离的完整版本数据。

**改动**：

- 新增 `GET /api/v1/accounts/{account_id}/positioning/versions/{version}`。
- 复用现有 `PositioningVersionDto`，服务层按账号与版本查询；不存在时返回稳定错误码和中文错误。
- 摘要由真实的目标受众与内容支柱派生；创建时保存可读摘要，读取旧数据时兼容旧泛化摘要。
- 更新 Desktop Runtime Client、类型契约与缓存失效规则。

**验收**：详情字段完整、跨账号不可读取、旧 `v1` 立即得到可读摘要、接口信封与错误格式一致。

**回退点**：新增 GET 接口可独立回退，不修改既有版本数据；摘要兼容逻辑不写回旧记录。

### J3：定位详情、编辑与状态体验

**目标**：完成用户可理解、可查看、可修改的页内闭环。

**改动**：

- 当前卡片改为真实受众、方向和标签摘要。
- 增加定位版本详情面板及加载、空、正常、错误、重试状态。
- 增加 `toPositioningDraft` 映射，支持从任意版本预填编辑器。
- 明确“保存为新版本”与“设为使用中”，保存后刷新列表、详情与全局账号知识状态。
- 同步 Light / Dark，以及桌面宽屏与紧凑窗口布局。

**验收**：用户无需猜测 `v1` 内容即可查看；从 v1 修改后得到 v2，v1 保持不变且仍可追溯。

**回退点**：详情面板和预填编辑可独立关闭，保留既有新建与激活能力。

### J4：文档、回归与测试包

**目标**：完成跨层契约和可交付验证。

**改动**：

- 更新 `docs/api/v1/account-knowledge.md` 与 `docs/RUNTIME-API-CALLS.md`，补齐地址、方法、参数、响应、错误码和示例。
- 按 `docs/VERSIONING.md` 校验 `0.4.8` 的所有源码镜像；在设置或诊断信息中显示应用版本与 build ID，便于用户反馈时定位制品。
- 执行改动相关 Desktop / Runtime 测试、TypeScript 类型检查及一条账号工作区主链回归。
- 在现有 P0-G 制品链上重新构建免安装 EXE 测试候选，并记录 SHA256 与验证结果。

**验收**：接口文档与实现一致；测试通过；新候选包能完成定位详情、修改和未保存决策链路。

**回退点**：制品不覆盖上一个可用候选，按 manifest 与 SHA256 独立保留。
