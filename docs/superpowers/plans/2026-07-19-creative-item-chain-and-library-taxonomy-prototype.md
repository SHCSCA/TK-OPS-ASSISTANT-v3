# TK-OPS 创作对象主链与内容库分类交互原型计划

> 日期：2026-07-19  
> 状态：已完成  
> 类型：多页交互原型重构  
> 目标终端：Windows PC 桌面应用，不考虑手机端适配  
> 前置真源：`docs/PRD.md`、`docs/UI-DESIGN-PRD.md`、`docs/ARCHITECTURE-BOOTSTRAP.md`  
> 审计证据：`docs/prototypes/tk-ops-account-workspace/audit-2026-07-19-creative-chain/README.md`

## 1. 背景与根因

上一版原型补齐了脚本与选题、分镜规划、视频拆解和媒体工具箱的入口，但只完成了“页面存在”，没有完成“对象接力”。现状主要有五个断点：

1. 选题、脚本、分镜、批次条目和内容资产存储在不同数据集合中，只通过相同标题形成表面关联。
2. “新建选题”只有演示 Toast，没有创建、保存、选中、生成脚本等后续交互。
3. 分镜页只能生成或重新生成，缺少确认和生产交接。
4. 视频拆解结果缺少关键词、证据、可选区块和回流影响预览。
5. 内容库没有沿用项目现有的视频、图片、音频、文档分类模式。

本轮不新增主导航，也不恢复剪辑工作台。重点是落实产品真源已经定义的 `ContentItem`，让现有五页组成一条可理解、可操作、可追溯的创作链。

## 2. 产品结论

### 2.1 单条内容是主对象，批量生产是编排层

统一关系：

```text
Account
├── ContentItem
│   ├── TopicBrief
│   ├── ScriptVersion[]
│   ├── StoryboardVersion[]
│   ├── SourceReference[]
│   └── ProductionReference[]
├── ProductionBatch
│   └── BatchEntry[]
│       └── ContentVariant
└── AssetLibrary
    └── Asset[]
```

- `ContentItem` 是一条准备生产的视频内容，不是一个文件，也不是一个批次。
- 选题、采用脚本和确认分镜是同一 `ContentItem` 的三个创作阶段。
- `ProductionBatch` 包含一个或多个 `BatchEntry`；每个条目引用一个 `ContentItem` 的已采用脚本版本与已确认分镜版本。
- “生成单条视频”不创建第二套链路；系统自动创建一个仅含一条内容的批次。
- 批次执行后生成 `ContentVariant` 与多个资产，全部进入当前账号内容库。

### 2.2 视频拆解是上游来源，不是必经阶段

```text
本地视频 / 当前账号视频资产 / 媒体工具输出
→ 视频拆解
→ 脚本片段 + 关键词 + 关键帧 + 内容结构
→ 新建选题 / 新建脚本版本 / 新建分镜版本 / 写入知识
→ 回到统一 ContentItem 主链
```

视频拆解与批量生产的关系不是“先拆解再批量生产”，而是“拆解可以为一个或多个 `ContentItem` 提供创作依据”。没有拆解来源的内容也可以正常完成生产。

### 2.3 内容库采用双层分类

主类型与当前项目资产中心保持一致：

- 全部
- 视频
- 图片
- 音频
- 文档

次级用途与来源用于进一步筛选：

- 成片
- 创作素材
- 脚本 / 字幕等文档
- 模板
- 拆解输出
- 媒体工具输出
- 本地导入

这样不会把“模板”和“视频”放在同一分类维度，也能保留现有内容库对模板、脚本、版本和来源的追溯能力。

## 3. 统一交互骨架

### 3.1 创作链头部

脚本与选题、分镜规划、批量生产详情三处复用低高度 `CreativeChainHeader`：

```text
选题  →  脚本  →  分镜  →  生产  →  成片
```

头部只显示：

- 当前 `ContentItem` 标题。
- 五阶段状态：未开始、进行中、待确认、已确认、异常、已完成。
- 当前阶段的一个主动作。
- “查看来源 / 版本 / 批次”进入 Detail Panel，不在主界面堆叠信息。

头部不是新的全局步骤条；它只在当前内容对象的工作面出现，避免增加侧栏噪音。

### 3.2 状态与切换规则

- 选择另一个选题时，同时切换其脚本、分镜、生产引用和资产引用。
- 存在未保存脚本或分镜编辑时，切换对象必须保存、放弃或取消。
- 脚本修订后，已有分镜标记为“基于旧脚本”，不得静默更新。
- 分镜只有在所有必需镜头就绪、异常已处理后才能确认。
- 已进入生产的内容保留不可变脚本和分镜引用；后续修改创建新版本，不改变运行中的批次。
- 账号切换后，所有 `ContentItem`、批次条目、拆解来源和资产筛选全部切换到目标账号。

## 4. 页面设计

### 4.1 脚本与选题

#### 页面结构

- 顶部：创作链头部；右侧主动作根据状态显示“新建选题”“AI 生成脚本”或“确认脚本并进入分镜”。
- 左侧：选题列表，展示标题、内容支柱和阶段状态，不再用勾选图标暗示不明含义。
- 中间：策划摘要与脚本工作面。
- 右侧 Detail Panel：完整简报、来源、版本、知识快照与 AI 作业。

#### 新建选题

“新建选题”打开居中轻量向导，第一步选择来源：

1. 手动创建。
2. 按当前账号定位 AI 推荐。
3. 从视频拆解结果创建。

手动创建默认只显示六项：

- 选题标题。
- 内容支柱。
- 目标受众。
- 创作角度。
- 目标时长。
- 来源或参考。

创建成功后：

- 生成当前账号的 `ContentItem`。
- 自动选中新内容。
- 创作链状态变为“选题已就绪”。
- 中间显示脚本空态，主动作变为“AI 生成脚本”。
- 提供“继续完善简报”作为次动作。

AI 推荐允许选择一条或多条候选选题；采用后每条候选都生成独立 `ContentItem`，后续可批量生成脚本草稿。

### 4.2 分镜规划

#### 页面结构

- 顶部：创作链头部，显示当前内容、脚本版本和分镜状态。
- 左侧：已采用脚本的段落锚点。
- 中间：镜头列表或两列镜头板。
- 右侧 Detail Panel：镜头高级字段、生成记录和版本。

#### 分镜完成后的生产交接

页面主动作按状态切换：

- 无分镜：`AI 生成分镜`。
- 有异常：`处理异常镜头`。
- 已就绪：`确认分镜`。
- 已确认：`进入生产`。

“进入生产”打开 `ProductionHandoffDialog`：

1. `生成单条视频`：创建一个单条批次并进入批次详情。
2. `加入现有批次`：展示当前账号可接收内容的批次。
3. `创建新批次`：输入批次名称和必要执行配置后加入。

交接确认区域明确列出：内容标题、采用脚本版本、确认分镜版本、知识快照和目标批次，避免用户不知道生产使用了哪一版。

### 4.3 批量生产

批量生产页从“结果列表”改为“批次编排与执行”。

#### 批次列表与详情

- 页面顶部可切换批次并新建批次。
- 详情区保留整体阶段、进度、取消、重试和异常优先筛选。
- 内容条目新增来源与就绪列：选题、脚本、分镜、生产、输出。
- 每个条目可打开对应 `ContentItem`，不会只看到同名成片。
- 条目未准备好时显示唯一阻断原因和推荐动作，例如“脚本未采用”或“分镜有 1 个异常镜头”。

#### 新建批次入口

保留原三种输入方式，并补足与创作主链的关系：

- `选择已确认内容`：消费一个或多个已完成分镜的 `ContentItem`。
- `AI 主题`：在批次内创建多个 `ContentItem`，仍按选题、脚本、分镜阶段推进。
- `固定脚本`：为每条脚本创建 `ContentItem`，脚本作为已导入版本。
- `已有素材`：为选中的视频、图片或文档素材创建内容对象或生产引用。

批次详情不重复编辑脚本正文和分镜正文；点击相应阶段回到对应工作面。

### 4.4 视频拆解

拆解结果改为四个标签页：

#### 脚本

- 按时间段展示完整转写或结构化脚本段落。
- 每段显示时间码、说话内容、段落作用和置信状态。
- 支持勾选片段后“新建选题”“创建脚本草稿”或“追加到现有脚本新版本”。

#### 关键词

- 分为主题、人物 / 对象、视觉元素、动作、语气五组。
- 关键词显示权重、证据时间点和命中次数。
- 支持勾选关键词写入选题标签、脚本简报或当前账号知识库。

#### 关键帧

- 使用真实可用帧时展示缩略图；无真实帧时使用中性空态，不伪造画面。
- 卡片显示时间码、画面摘要、主体、构图 / 镜头、可复用用途。
- 可将选中帧作为分镜参考或内容库图片资产。

#### 结构

- 用时间比例条展示 Hook、展开、证据、CTA 等结构段。
- 每段显示起止时间、占比、作用、证据脚本和对应关键帧。
- 支持一键复制为新选题结构模板或脚本大纲。

#### 应用结果

“应用结果”不再只列三个目标。弹层必须预览将创建或修改的对象：

- 创建几个新选题。
- 创建哪条脚本的哪个新版本。
- 创建哪条分镜的哪个新版本。
- 写入哪些知识条目或资产。

覆盖现有内容时显示影响，默认始终新建版本。

### 4.5 内容库

沿用 `apps/desktop` 当前资产中心的成熟模式：搜索 + 类型标签 + 排序 + 资产墙 + Detail Panel。

#### 主筛选

```text
全部 | 视频 | 图片 | 音频 | 文档
```

#### 次筛选

- 用途：成片、素材、脚本、字幕、模板。
- 来源：本地导入、AI 生产、视频拆解、媒体工具。
- 状态：可用、生成中、文件缺失、处理失败。

#### 资产卡与详情

- 视频：缩略图、时长、分辨率、版本、来源批次。
- 图片：缩略图、尺寸、用途、来源镜头或工具任务。
- 音频：时长、格式、用途、来源内容。
- 文档：文档类型、关联选题 / 脚本 / 分镜、版本。
- Detail Panel 显示真实文件路径、来源对象、配置版本、引用影响和修复动作。

模板通过 `purpose=template` 表达，工具输出通过 `source=media-tool` 表达，不再与媒体类型混为同一层级。

## 5. 原型数据与状态调整

### 5.1 数据模型

新增或重构原型模型：

- `ContentItem`：`id`、`accountId`、`title`、`topicBrief`、`stage`、`sourceReferences`、`scriptVersionIds`、`storyboardVersionIds`、`productionReferences`、`assetIds`。
- `ScriptVersion`：增加 `contentItemId`、采用状态和不可变修订引用。
- `StoryboardVersion`：增加 `contentItemId`、`sourceScriptVersionId`、确认状态。
- `BatchEntry`：增加 `contentItemId`、`scriptVersionId`、`storyboardVersionId`、阶段与阻断原因。
- `DeconstructionResult`：拆分 `scriptSegments`、`keywords`、`keyframes`、`structureSegments`。
- `Asset`：统一 `type`、`subtype`、`purpose`、`source`、`mime`、`status`、`version`、`contentItemId`、`batchId`、`metadata`、`tags`。

### 5.2 状态模块

为避免继续膨胀 `useCreativeWorkflowState.js`，按职责拆分：

- `useContentItemState.js`：选题、脚本、分镜和链路切换。
- `useProductionHandoffState.js`：分镜确认、单条生产和加入批次。
- `useDeconstructionState.js`：拆解标签、选择、应用预览和回流。
- `useAssetLibraryState.js`：类型、用途、来源筛选和资产详情。
- `useWorkspaceState.js`：只负责组合账号范围状态与全局浮层。

所有演示异常通过现有 `prototypeLogger` 记录并转为中文可见反馈；配置继续使用 `configBus`，不在页面中保存独立配置。

## 8. 必须验证的交互主链

1. 手动新建选题 → AI 生成脚本 → 采用脚本 → 生成并确认分镜 → 生成单条视频 → 打开单项批次 → 成片进入视频分类。
2. AI 批量采用多个选题 → 批量生成脚本草稿 → 分别确认分镜 → 加入同一批次 → 查看每条内容来源与状态。
3. 拆解视频 → 查看时间码脚本 → 筛选关键词 → 查看结构证据 → 创建新选题 → 回到脚本页继续创作。
4. 拆解关键帧 → 选中帧写入分镜参考和图片资产 → 在内容库按图片 / 拆解输出筛选。
5. 生产或媒体工具输出 → 内容库按视频、图片、音频、文档筛选 → 打开详情并追溯批次 / 内容对象。
6. 脚本更新 → 分镜出现版本不一致 → 用户选择同步或沿用旧版 → 运行中批次引用不被改变。
7. 切换账号 → 当前内容、批次、拆解、筛选和详情全部切换且不串数据。

## 9. 验收标准

| 维度 | 验收要求 |
| --- | --- |
| 对象一致性 | 同一条内容在选题、脚本、分镜、批次和资产详情中使用同一 `ContentItem` 引用 |
| 新建选题 | 用户无需猜测即可完成创建，并立即看到下一步“生成脚本” |
| 分镜后续 | 分镜确认后可明确选择单条生产或加入批次，版本与目标可见 |
| 批量关系 | 批次包含一条或多条内容，每条都能查看选题、脚本、分镜就绪状态和来源 |
| 拆解结果 | 脚本、关键词、关键帧、结构有具体可选结果、证据和回流预览 |
| 内容库 | 支持全部、视频、图片、音频、文档主分类，并可按用途与来源细分 |
| 低噪音 | 默认只突出当前对象、当前阶段、异常和一个主动作；高级信息进入 Detail Panel |
| 状态完整 | 加载、空、正常、异常、确认、取消、失败、重试和完成均有可见反馈 |
| 账号隔离 | 切换账号后所有创作对象、批次、拆解和资产严格隔离 |
| PC 适配 | 桌面宽屏与紧凑窗口均可完成主链，Light / Dark 语义一致 |
| 工程质量 | 页面、状态、数据、样式按职责拆分，无超大文件；测试和构建通过 |

## 10. 明确边界

- 本轮只修改本地交互原型和对应真源，不接入生产 Runtime。
- 不新增导航页，不恢复 AI 剪辑工作台、多轨时间线或专业剪辑能力。
- 不引入手机端布局；只验证 PC 宽屏和紧凑窗口。
- 不制造真实业务指标、真实 Provider 结果、真实关键帧或真实发布回执。
- 视频拆解无真实画面时使用中性空态或文本证据，不用假图片伪装结果。
- 下载、去水印等媒体工具的权利与安全边界保持不变。
- 若实现范围超出本计划，必须先更新计划 / 规格并重新批准。
