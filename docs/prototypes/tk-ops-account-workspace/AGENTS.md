# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

## Durable product decisions

- The prototype is PC-only and account-scoped. Switching the account replaces the entire workspace context, including knowledge, content, AI recipe, tasks, assets, publishing, and review.
- Keep the interface low-noise: one dominant action per state, progressive disclosure, compact tables, and no dashboard card walls.
- Do not restore the editing workbench, manual timeline, mobile layout, team back office, CRM, or fake business metrics.
- Video deconstruction results use readable semantic tables for scripts, keywords, real keyframes, and structure; missing real media uses neutral empty states.
- Pixelle-Video is a capability reference, not a UI source. Adopt composable providers, capability-driven parameters, staged progress, prompt styles, templates, and asset analysis while excluding action transfer, digital humans, voice cloning, raw workflow editing, and unsafe logging.
